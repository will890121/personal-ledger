# 待辦：明確登記商家

提出時間：2026-09-26（原題為「商家記憶與預設分類」，設計途中改題）

## 這張待辦剩下什麼

原本的構想是：「一蘭拉麵 200」這種句子，把不認得的詞記進 `merchants` 並給它預設分類，
下次直接命中。設計時使用者問了一句「如果我今天輸入的是『牛排』，這樣也會變成商家嗎？」
—— 會，而且那正是這個構想的要害。

殘餘文字偵測只知道「這個詞我不認得」，分不出「一蘭拉麵」是店名而「牛排」是品項，也分不出
「雜支」兩者都不是。把品項寫進 `merchants` 會讓預覽與 `/recent` 出現「商家：牛排」，污染
商家這個概念。

因此「同一個詞不要再問我第二次」這個需求改由**使用者自訂分類關鍵字**解決（migration 0007、
`docs/domain/category-model.md`），它不需要分辨店名與品項。

**剩下的是真正的商家需求**：讓使用者明確說「一蘭拉麵是一家店」，好讓交易填上 `merchantId`、
預覽與 `/recent` 顯示「商家：一蘭拉麵」，並且未來能按商家做統計。

## 缺口

1. 沒有任何辦法登記新商家。`merchants` 目前只有 M1 留下的 Uber，parser 只比對已登記的商家。
2. `merchants` 沒有預設分類欄位。唯一的商家→分類對應寫在 `category-keywords.ts` 的商家表裡
   （`Uber → 交通`），使用者無法自行新增。

## 構想

一個明確的指令，而不是靠猜：

```
/merchant 一蘭拉麵 餐飲     → 建立商家並設定預設分類
/merchant 一蘭拉麵          → 只建立商家，不設分類
/merchants                  → 列出、可刪除
```

指令比自動偵測適合這件事：使用者說「這是一家店」時是明確的，不需要我們去猜。自動偵測已經
由自訂關鍵字覆蓋掉大部分的痛點，剩下的商家需求頻率低很多。

需要的東西：`merchants.default_category_id`（新 migration）、指令 handler、`expenseShell` 的
商家查詢改讀資料庫欄位而不是程式裡的靜態表。

## 尚未決定

排在哪個里程碑，以及使用者是否真的需要按商家統計——若不需要，這張待辦可以直接關掉。
