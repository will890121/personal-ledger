# 待辦：商家記憶與預設分類

提出時間：2026-09-26
起因：使用者問「一蘭拉麵 200」這種店名層級的消費能不能支援。

## 問題

關鍵字對照表（`src/parser/category-keywords.ts`）只放餐別與明確品類。店名與細品項不放進表裡
是刻意的決定：表一膨脹就變成替使用者猜測他會吃什麼，而且永遠追不完。

因此現在「一蘭拉麵 200」會落到「待分類 + 追問分類」，每次都要重新選一遍，店名也不會留在
結構化欄位裡（只保存在 `rawInputSnapshot`）。

## 現有基礎

- `merchants` 表已存在，parser 會用 `text.includes(merchant.name)` 比對**已登記**的商家，
  命中就填 `merchantId`。
- 預覽與 `/recent` 都已經會印出「商家：<名稱>」（`format-preview.ts`、`handlers/transactions.ts`）。
- 交易對象已經有「未建立就追問、確認後建立」的流程（`create-counterparty` callback 與
  `PendingField.proposedName`），形狀可以直接沿用。

## 缺口

1. `merchants` 沒有分類欄位，記不住「這家店屬於哪個分類」。目前唯一的商家→分類對應寫在
   程式裡（`Uber → 交通`），使用者無法自行新增。
2. 未登記的名字對 parser 完全不存在，沒有任何辦法登記新商家。

## 構想

```
使用者：一蘭拉麵 200
Bot：  尚未認識「一蘭拉麵」，要記成商家嗎？
       [ 記住並選分類 ] [ 只記這一筆 ] [ 取消 ]
使用者：（選 餐飲）
→ 建立商家「一蘭拉麵」，預設分類 餐飲

下次「一蘭拉麵 200」→ 直接成草稿，商家：一蘭拉麵、分類 餐飲，零追問
```

需要的東西：

- 新 migration 加 `merchants.default_category_id`（外鍵指向 `categories`）。
- **殘餘文字偵測**：把金額、日期詞、已知帳戶／商家／分類關鍵字都剝掉之後，句子還剩下
  非空的一段，就提議它是商家。只在「關鍵字沒命中」時才觸發，「晚餐 150」不會被騷擾。
- 一組 callback 與追問流程，沿用 `create-counterparty` 的形狀。

## 風險

誤傳會長出垃圾商家。靠「要確認才建立」壓住，與交易對象同一套做法。
