# 驗收：使用者自訂分類關鍵字

對象：migration `0007_user_category_keywords.sql`、`src/parser/residual-text.ts`、
`matchUserKeyword`、`formatKeywordOffer` 與 `k:` callback。

起因：使用者問「一蘭拉麵 200」這種店名層級的消費能不能支援。設計途中改了方向——見
`docs/domain/category-model.md` 的「為什麼不是商家記憶」與
`docs/todo/merchant-registration.md`。

## 關卡一：自動驗證

- `pnpm check` **exit 0**：57 檔 / **381 測試**（起點 345）。
  - 第一次送審時我宣稱「全綠」是錯的：當時用 grep 過濾 `pnpm check` 的輸出，樣式寫成複數
    `problems`，而 eslint 印的是 `1 problem`，因此漏看一個 lint 錯誤。之後一律看 exit code。
- 變異驗證：
  - `MIN_LENGTH` 由 2 降為 1（讓「國泰卡刷 1200」提議單字「刷」）→ 2 條紅。
  - 使用者關鍵字不再優先於內建表 → 4 條紅。
  - 接受多段殘餘中的第一段 → 2 條紅。
  - 自訂關鍵字改成最短優先 → 2 條紅。
  - 拿掉「只在分類欄位才提議」的條件 → 1 條紅。
